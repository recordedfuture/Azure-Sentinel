## Context

`Solutions/Recorded Future` uses the Azure Logic Apps managed connector `azureloganalyticsdatacollector` for all data ingestion into Log Analytics. This connector wraps the legacy HTTP Data Collector API, which Microsoft is retiring on **September 14, 2026**. The 4 affected playbooks are:

- `RecordedFuture-Playbook-Alert-Importer` → `RecordedFuturePlaybookAlerts_V2_CL`
- `RecordedFuture-Alert-Importer` → `RecordedFuturePortalAlerts_V2_CL`
- `RecordedFuture-ThreatMap-Importer` → `RecordedFutureThreatMap_V2_CL`
- `RecordedFuture-ThreatMapMalware-Importer` → `RecordedFutureThreatMapMalware_V2_CL`

The replacement is the Azure Monitor Logs Ingestion API (REST), which requires a Data Collection Endpoint (DCE), a Data Collection Rule (DCR), a pre-provisioned Log Analytics Custom Table, and Managed Identity authentication.

Reference implementation in this repository: `Solutions/SOCRadar/Playbooks/SOCRadar-Alarm-Import/azuredeploy.json` (all-in-one pattern — best reference).

## Goals / Non-Goals

**Goals:**
- All 4 playbooks use the Logs Ingestion API
- Each playbook's `azuredeploy.json` is self-contained: DCE, DCR, table, role assignment, Logic App — all in one template
- No workspace shared key required at deployment or runtime
- New `_V2_CL` table names with bare column names (no `_s`/`_d`/`_b` suffixes) — clean break from legacy tables, no migration tooling required
- `createUiDefinition.json` updated to declare the new resource providers
- Migration guide shipped with the solution

**Non-Goals:**
- Migrating `Package/mainTemplate.json` manually — regenerated by `createSolution.ps1` via CI
- In-place schema migration of existing `_CL` tables

## Decisions

### D1 — All infrastructure in a single `azuredeploy.json` per playbook

**Decision:** Embed DCE, DCR, table, and role assignment directly in each playbook's ARM template.

**Rationale:** Matches the SOCRadar reference pattern. Self-contained; no cross-template dependency chain.

**Alternatives considered:** Separate infrastructure template (Checkmarx pattern) — rejected: adds deployment ordering complexity with no benefit for single-playbook solutions.

---

### D2 — System-Assigned Managed Identity per Logic App

**Decision:** Add `"identity": { "type": "SystemAssigned" }` to each Logic App; scope `Monitoring Metrics Publisher` role assignment to the DCR.

**Rationale:** No secrets to manage; identity lifecycle tied to the Logic App; role is narrowly scoped.

**Alternatives considered:** User-Assigned Managed Identity — rejected: extra resource and deployment dependency, no meaningful benefit.

---

### D3 — New `_V2_CL` table names; deploy-time parameter with default

**Decision:** All 4 tables use new `_V2_CL` names (e.g. `RecordedFuturePortalAlerts_V2_CL`). Each playbook exposes a `tableName` parameter defaulting to the appropriate `_V2_CL` name, baked into the DCR stream at deploy time.

**Rationale:** Reusing the old `_CL` name hits the `Tables - Create Or Update` API which merges schemas additively — legacy `_s`-suffixed columns remain alongside bare-named columns, creating split-brain data. Deploying against an MMA-managed table may also be rejected outright. New `_V2_CL` names give a clean break: old tables untouched, new tables provisioned fresh, no migration tooling needed.

**Alternatives considered:** Same table name reuse — rejected (schema merge pollution, potential ARM rejection). Drop `_CL` suffix — rejected (Microsoft mandates `_CL` for custom tables; enforced by the API).

---

### D4 — `dynamic` columns for opaque/deeply-nested fields

**Decision:** `Entity` and `Documents` in `RecordedFuturePortalAlerts_V2_CL` declared as `dynamic`; array fields in ThreatMap tables (`alias`, `categories`, `log_entries`) also `dynamic`.

**Rationale:** Avoids column explosion for nested objects; preserves `mv-expand` / `parse_json` queryability.

---

### D5 — Payload shape: always a JSON array

**Decision:** The Logs Ingestion API requires a JSON array body. `RecordedFuture-Alert-Importer` previously posted a single object — it will be wrapped using `createArray(...)`.

**Rationale:** Mandatory API requirement; trivial expression change.

---

### D6 — ARM API versions

- DCE / DCR: `2024-03-11`
- Log Analytics Table: `2022-10-01`
- Role Assignment: `2022-04-01`
- Logic App: `2019-05-01` (existing, unchanged)

## Risks / Trade-offs

- **Existing customers must update saved queries to use new `_V2_CL` table names** → Mitigation: migration guide documents the rename; old `_CL` tables remain queryable for historical data so nothing breaks immediately.

- **Side-by-side upgrade is safe** → Old and new playbooks target different table names; both can run in parallel during transition.

- **`contentVersion` bump policy unclear** → Mitigation: bump each playbook's minor version independently. Confirm with team before merging.

- **Role assignment race condition** → Mitigation: `dependsOn` lists both DCR and Logic App; ARM resolves principal ID via `reference(...).identity.principalId`.

- **1 MB payload limit per POST** → Mitigation: ThreatMap importers post bulk arrays. Assess actual payload sizes; add batching logic (see Checkmarx reference) if needed.

## Migration Plan

### Fresh deployment (new customers)
1. Deploy updated template; provide `workspaceResourceId` and `workspaceName`.
2. ARM creates DCE, DCR, `_V2_CL` table, Logic App, and role assignment. No workspace key needed.
3. Verify data flows into the `_V2_CL` table within one trigger interval.

### Upgrade path (existing customers)
1. Deploy the new template — it targets a different `_V2_CL` table, so there is no conflict with the existing deployment.
2. Verify data flows into the new `_V2_CL` table.
3. Update any saved KQL queries, alerts, or workbooks to point at the new `_V2_CL` table names.
4. Decommission the old playbook and its `azureloganalyticsdatacollector` connection once satisfied.
5. Old `_CL` tables with historical data can be retained or deleted per retention policy.

### Rollback
Re-deploy the previous version from source control. The legacy connector remains functional until September 14, 2026.
