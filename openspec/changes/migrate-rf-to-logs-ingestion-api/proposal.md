## Why

Microsoft is retiring the HTTP Data Collector API (wrapped by the `azureloganalyticsdatacollector` Logic Apps connector) on **September 14, 2026**. All 4 playbooks in `Solutions/Recorded Future` use this connector for data ingestion — after the retirement date they will silently stop writing data to Log Analytics.

## What Changes

- **BREAKING**: Replace `azureloganalyticsdatacollector` API connection with direct HTTP calls to the Azure Monitor Logs Ingestion API using Managed Identity authentication
- **BREAKING**: New `_V2_CL` table names — new data lands in clean, versioned tables with bare column names; old `_CL` tables are left untouched and continue to hold historical data
- **BREAKING**: `workspaceId` and `workspaceKey` deploy parameters removed; replaced by `workspaceResourceId` and `workspaceName`
- Add Data Collection Endpoint (DCE), Data Collection Rule (DCR), and Log Analytics Table as ARM resources in each playbook's `azuredeploy.json`
- Add System-Assigned Managed Identity to each Logic App and a `Monitoring Metrics Publisher` role assignment scoped to each DCR
- Wrap single-object payloads in an array where required by the new API
- Add `Microsoft.Insights/dataCollectionEndpoints` and `Microsoft.Insights/dataCollectionRules` to `resourceProviders` in `createUiDefinition.json`
- Write a migration guide documenting the upgrade path, new table names, and side-by-side deployment option

## Capabilities

### New Capabilities

- `logs-ingestion-api-rf`: Migration of 4 `Solutions/Recorded Future` playbooks to the Logs Ingestion API — DCE/DCR/table/role ARM resources, updated Logic App actions, and a migration guide

### Modified Capabilities

## Impact

- **4 playbook ARM templates** modified: `RecordedFuture-Alert-Importer`, `RecordedFuture-Playbook-Alert-Importer`, `RecordedFuture-ThreatMap-Importer`, `RecordedFuture-ThreatMapMalware-Importer`
- **`Solutions/Recorded Future/Package/createUiDefinition.json`** updated
- **Existing customers** retain full access to old `_CL` tables; new data flows into separate `_V2_CL` tables — no migration tooling required and no schema collision
- **New deployment prerequisites**: deploying identity must have permission to create DCE, DCR, and role assignments; `Microsoft.Insights` provider must be registered
- **No changes** to `Package/mainTemplate.json` — regenerated by `createSolution.ps1` via CI
