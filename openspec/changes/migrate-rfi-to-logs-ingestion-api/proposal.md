## Why

Microsoft is retiring the HTTP Data Collector API (wrapped by the `azureloganalyticsdatacollector` Logic Apps connector) on **September 14, 2026**. All 5 playbooks in `Solutions/Recorded Future Identity` use this connector for data ingestion — after the retirement date they will silently stop writing data to Log Analytics.

## What Changes

- **BREAKING**: Replace `azureloganalyticsdatacollector` API connection with direct HTTP calls to the Azure Monitor Logs Ingestion API using Managed Identity authentication
- **BREAKING**: New `_V2_CL` table names — new data lands in clean, versioned tables with bare column names; old `_CL` tables are left untouched and continue to hold historical data
- **BREAKING**: KQL queries in `RFI-search-workforce-user` and `RFI-search-external-user` must be updated to target the new `_V2_CL` table names and bare column names (no `_s`/`_d`/`_b` suffixes)
- **BREAKING**: `workspaceResourceId` deploy parameter added — the existing `workspace_name` parameter is retained as-is and reused for the Log Analytics table ARM resource name
- **BREAKING**: `RFI-lookup-and-save-user` loses runtime-dynamic table name override; table name is now fixed at deploy time via parameter
- Add Data Collection Endpoint (DCE), one or more Data Collection Rules (one per target table), Log Analytics Tables, and role assignments as ARM resources in each playbook's `azuredeploy.json`
- Add System-Assigned Managed Identity to each Logic App and a `Monitoring Metrics Publisher` role assignment scoped to each DCR
- Remove `Check_if_table_exists` and `Create_table_if_missing` actions from `RFI-Playbook-Alert-Importer-LAW` (table provisioning is now declarative in ARM)
- Write a migration guide documenting the upgrade path, new table names, KQL query update instructions, and side-by-side deployment option

## Impact

- **5 playbook ARM templates** modified: `RFI-Playbook-Alert-Importer-LAW`, `RFI-Playbook-Alert-Importer-LAW-Sentinel`, `RFI-search-workforce-user`, `RFI-search-external-user`, `RFI-lookup-and-save-user`
- **`Solutions/Recorded Future Identity/Package/createUiDefinition.json`** updated
- **KQL queries** in two RFI playbooks updated to new table names and bare column names
- **Existing customers** retain full access to old `_CL` tables; new data flows into separate `_V2_CL` tables — no migration tooling required and no schema collision
- **New deployment prerequisites**: deploying identity must have permission to create DCE, DCR, and role assignments; `Microsoft.Insights` provider must be registered
- **No changes** to `Package/mainTemplate.json` — regenerated by `createSolution.ps1` via CI
