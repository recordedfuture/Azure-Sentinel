## Context

`Solutions/Recorded Future Identity` uses the Azure Logic Apps managed connector `azureloganalyticsdatacollector` for all data ingestion into Log Analytics. This connector wraps the legacy HTTP Data Collector API, which Microsoft is retiring on **September 14, 2026**. The 5 affected playbooks are:

- `RFI-Playbook-Alert-Importer-LAW` → `RecordedFutureIdentity_PlaybookAlertResults_V2_CL`
- `RFI-Playbook-Alert-Importer-LAW-Sentinel` → `RecordedFutureIdentity_PlaybookAlertResults_V2_CL`
- `RFI-search-workforce-user` → `RecordedFutureIdentity_LeakedCredentials_CredentialDumps_V2_CL` + `RecordedFutureIdentity_LeakedCredentials_MalwareLogs_V2_CL`
- `RFI-search-external-user` → `RecordedFutureIdentity_LeakedCredentials_MalwareLogs_V2_CL`
- `RFI-lookup-and-save-user` → `RecordedFutureIdentity_UsersLookupResults_V2_CL`

The replacement is the Azure Monitor Logs Ingestion API (REST), which requires a DCE, DCR(s), pre-provisioned Log Analytics Custom Table(s), and Managed Identity authentication.

Reference implementation in this repository: `Solutions/SOCRadar/Playbooks/SOCRadar-Alarm-Import/azuredeploy.json` (all-in-one pattern with multiple DCRs — best reference).

## Goals / Non-Goals

**Goals:**
- All 5 playbooks use the Logs Ingestion API
- Each playbook's `azuredeploy.json` is self-contained: DCE, DCR(s), table(s), role assignment(s), Logic App — all in one template
- `workspaceResourceId` added to each playbook (for the DCR `destinations.logAnalytics` block); existing `workspace_name` / `log_analytics_workspace_name` / `sentinel_workspace_name` parameters retained as-is and reused for the Log Analytics table ARM resource name — no workspace key or shared-key parameters existed to remove
- New `_V2_CL` table names with bare column names (no `_s`/`_d`/`_b` suffixes) — clean break from legacy tables, no migration tooling required
- KQL queries in `RFI-search-workforce-user` and `RFI-search-external-user` updated to new table names and bare column names
- `Check_if_table_exists` / `Create_table_if_missing` seed actions removed from `RFI-Playbook-Alert-Importer-LAW`
- Migration guide shipped with the solution

**Non-Goals:**
- Migrating `Package/mainTemplate.json` manually — regenerated by `createSolution.ps1` via CI
- In-place schema migration of existing `_CL` tables
- Supporting runtime-dynamic table name override in `RFI-lookup-and-save-user` — not possible with DCR-based ingestion

## Decisions

### D1 — All infrastructure in a single `azuredeploy.json` per playbook

**Decision:** Embed DCE, DCR(s), table(s), and role assignment(s) directly in each playbook's ARM template.

**Rationale:** Matches the SOCRadar reference pattern. Self-contained; no cross-template dependency chain. SOCRadar demonstrates the multi-DCR variant (2 DCRs, 2 tables in one template) directly applicable to `RFI-search-workforce-user`.

---

### D2 — System-Assigned Managed Identity per Logic App

**Decision:** Add `"identity": { "type": "SystemAssigned" }` to each Logic App; scope `Monitoring Metrics Publisher` role assignment(s) to each DCR.

**Rationale:** No secrets to manage; identity lifecycle tied to the Logic App; roles narrowly scoped per DCR.

**Validated by POC (2026-05-25):** System-assigned identity works end-to-end. HTTP 204 from Logs Ingestion API confirmed. No race condition observed. No user-assigned identity fallback needed.

---

### D2b — `streamDeclarations` keys must be literal strings

**Decision:** Hard-code the stream name as the property key in `streamDeclarations` (e.g. `"Custom-RecordedFutureIdentity_PlaybookAlertResults_V2_CL": { ... }`). Do not use ARM expressions as object keys.

**Rationale:** Discovered during POC — ARM does not allow expressions as JSON property key names. The CLI fails with a cryptic "content already consumed" error if attempted. Values (in `dataFlows[].streams[]` etc.) may still use `"[variables('StreamName')]"` as normal.

---

### D3 — New `_V2_CL` table names; deploy-time parameter with default; no runtime override

**Decision:** All 5 target tables use new `_V2_CL` names. Each playbook exposes a `tableName` parameter (or two, for `RFI-search-workforce-user`) defaulting to the appropriate `_V2_CL` name, baked into the DCR stream at deploy time. The runtime-dynamic `triggerBody()?['lookup_results_log_analytics_custom_log_name']` override in `RFI-lookup-and-save-user` is removed.

**Rationale:** Reusing old `_CL` names causes additive schema merge (legacy `_s`-suffixed columns remain), potential ARM rejection for MMA-managed tables, and split-brain data. New `_V2_CL` names give a clean break. DCR streams are fixed at deploy time; runtime override is not supported by the API.

**Alternatives considered:** Same table name reuse — rejected. Drop `_CL` suffix — rejected (Microsoft mandates it; enforced by the API).

---

### D4 — Remove seed actions from `RFI-Playbook-Alert-Importer-LAW`

**Decision:** Remove `Check_if_table_exists` and `Create_table_if_missing` Logic App actions.

**Rationale:** These existed solely to work around the legacy API's lack of schema pre-provisioning. The new ARM template provisions the table declaratively before the Logic App ever runs.

---

### D5 — `dynamic` columns for deeply-nested fields

**Decision:** `identities` in `RecordedFutureIdentity_UsersLookupResults_V2_CL` declared as `dynamic`. Top-level scalars (`count`, `next_offset`) typed explicitly.

**Rationale:** Avoids an explosion of deeply nested flat columns; `mv-expand` / `parse_json` is the standard KQL pattern for such structures.

---

### D6 — ARM API versions

- DCE / DCR: `2024-03-11`
- Log Analytics Table: `2022-10-01`
- Role Assignment: `2022-04-01`
- Logic App: `2019-05-01` (existing, unchanged)

## Risks / Trade-offs

- **Existing customers must update saved queries to use new `_V2_CL` table names and bare column names** → Mitigation: migration guide provides explicit find-and-replace instructions; old `_CL` tables remain queryable so nothing breaks immediately.

- **Side-by-side upgrade is safe** → Old and new playbooks target different table names; both can run in parallel during transition.

- **`RFI-lookup-and-save-user` loses runtime table name override** → Mitigation: documented in migration guide; deploy-time parameter with default satisfies all standard deployments.

- **`contentVersion` bump policy unclear** → Bump each playbook's minor version independently. Confirm with team.

- **Role assignment race condition** → Mitigation: `dependsOn` lists both DCR and Logic App resources; ARM resolves principal ID via `reference(...).identity.principalId`.

## Migration Plan

### Fresh deployment (new customers)
1. Deploy updated template; provide `workspaceResourceId`. The existing workspace name parameter (`workspace_name` / `log_analytics_workspace_name` / `sentinel_workspace_name` depending on playbook) is retained from the previous deployment.
2. ARM creates DCE, DCR(s), `_V2_CL` table(s), Logic App, and role assignment(s). No workspace key needed.
3. Verify data flows into the `_V2_CL` table(s) within one trigger interval.

### Upgrade path (existing customers)
1. Deploy the new template — it targets different `_V2_CL` tables, so there is no conflict with the existing deployment.
2. Verify data flows into the new `_V2_CL` tables.
3. Update any saved KQL queries, alerts, or workbooks to use the new `_V2_CL` table names and bare column names.
4. Decommission the old playbook and its `azureloganalyticsdatacollector` connection once satisfied.
5. Old `_CL` tables with historical data can be retained or deleted per retention policy.

### Rollback
Re-deploy the previous version from source control. The legacy connector remains functional until September 14, 2026.
